# Performance Optimization

## Цель

Повысить скорость без ухудшения дизайна, SEO, аналитики, форм и функциональности.

## Обязательный порядок

1. Сними исходное состояние и перечисли главные узкие места.
2. Найди LCP-элемент, блокирующие ресурсы, тяжёлые изображения, шрифты и сторонние скрипты.
3. Вноси изменения малыми группами.
4. После каждой группы проверь визуальные и функциональные регрессии.

## Проверки

### Изображения

- реальные размеры соответствуют отображаемым;
- WebP/AVIF используются там, где это безопасно;
- у `<img>` заданы `width` и `height` или `aspect-ratio`;
- изображения ниже первого экрана используют `loading="lazy"`;
- LCP-изображение не lazy-load и получает приоритет только при необходимости;
- отсутствуют огромные фоновые изображения для мобильных устройств.

### Шрифты

- используются WOFF2;
- нет лишних начертаний;
- `font-display` выбран осознанно;
- preload применяется только к реально критичным шрифтам;
- fallback-метрики уменьшают сдвиги макета.

### CSS

- нет дублирующих и неиспользуемых крупных блоков;
- критический CSS минимален;
- некритичные стили не блокируют первый рендер без необходимости;
- анимации используют преимущественно `transform` и `opacity`.

### JavaScript

- скрипты подключаются с `defer`/`async` по назначению;
- нет тяжёлых библиотек ради одной функции;
- обработчики событий не создаются многократно;
- длительные задачи разбиты;
- сторонние виджеты загружаются после основного контента, если допустимо.

### Сеть и сервер

- включено сжатие;
- статике назначены корректные cache headers;
- нет цепочек редиректов;
- preconnect используется только для критичных внешних origin;
- не создаются дублирующие запросы.

## Запреты

- Не удаляй аналитику, формы, CRM, карту или чат без согласования.
- Не ухудшай SEO-контент ради балла Lighthouse.
- Не добавляй сборщик, фреймворк или библиотеку без необходимости.
- Не применяй preload ко всем ресурсам.

## Отчёт

Покажи: проблема → причина → изменение → ожидаемый эффект → проверка → возможный риск.
