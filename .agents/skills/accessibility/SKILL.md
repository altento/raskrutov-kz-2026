# Accessibility

## Цель

Проверять и исправлять доступность страниц без разрушения дизайна, SEO, форм и существующей бизнес-логики.

## Когда применять

- аудит WCAG и a11y;
- проблемы с контрастностью;
- управление с клавиатуры;
- focus states и focus order;
- подписи полей, кнопок и интерактивных элементов;
- alt-тексты изображений;
- семантика заголовков и landmarks;
- screen reader compatibility;
- мобильные touch targets.

## Обязательный порядок работы

1. Определи целевые страницы и пользовательские сценарии.
2. Не меняй визуальный стиль без необходимости.
3. Проверь HTML-семантику, keyboard navigation, focus, формы, изображения и контраст.
4. Исправляй причину проблемы, а не маскируй её дополнительным JavaScript.
5. После исправлений повторно проверь страницу на desktop и mobile.

## Проверки

### Семантика

- один содержательный `h1`;
- логичная последовательность `h2`–`h3`;
- `header`, `nav`, `main`, `footer` используются по назначению;
- кнопки реализованы через `button`, ссылки — через `a`;
- интерактивный `div` не используется без роли, keyboard handlers и focusability.

### Клавиатура и focus

- все элементы доступны через Tab;
- порядок фокуса соответствует визуальному порядку;
- focus indicator заметен и не удалён;
- модальные окна удерживают focus и возвращают его после закрытия;
- Escape закрывает диалог, если это ожидаемо;
- нет keyboard traps.

### Формы

- у каждого поля есть связанный `label`;
- `name`, `type`, `autocomplete`, `required` заданы корректно;
- ошибки сообщаются текстом, а не только цветом;
- статус отправки доступен через `aria-live`;
- placeholder не заменяет label.

### Изображения и иконки

- информативные изображения имеют осмысленный `alt`;
- декоративные изображения используют пустой `alt=""`;
- иконки-кнопки имеют доступное имя;
- текст не запечён в изображение без текстового эквивалента.

### Контраст и размеры

- обычный текст: минимум 4.5:1;
- крупный текст: минимум 3:1;
- важные границы и focus states различимы;
- touch target желательно не менее 44×44 CSS px;
- контент читается при увеличении до 200%.

## Ограничения проекта Raskrutov

- не ломать подключение `public.bundle`;
- не менять формы и интеграции без проверки их контракта;
- не удалять Schema.org, метрики и аналитику;
- сохранять адаптивность и текущую иерархию URL;
- учитывать правила `.cursor/rules/`.
