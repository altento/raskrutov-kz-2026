# Core Web Vitals

## Целевые ориентиры

- LCP: до 2,5 с на 75-м перцентиле.
- INP: до 200 мс на 75-м перцентиле.
- CLS: до 0,1 на 75-м перцентиле.

Лабораторные данные и реальные полевые данные не смешивать. Всегда указывать источник метрики.

## LCP

1. Определи точный LCP-элемент отдельно для мобильной и ПК-версии.
2. Проверь TTFB, очередность загрузки, размер ресурса и время рендера.
3. Для hero-изображения проверь:
   - корректный формат и размер;
   - отсутствие lazy loading;
   - `fetchpriority="high"` только при подтверждённой необходимости;
   - раннее обнаружение ресурса в HTML.
4. Уменьши render-blocking CSS/JS.
5. Не маскируй проблему искусственным удалением содержимого первого экрана.

## CLS

Проверяй:

- изображения и iframe без зарезервированного размера;
- поздно появляющиеся баннеры, шапки, cookie-блоки и формы;
- смену шрифтов и различие метрик fallback-шрифта;
- анимации свойств layout;
- динамически добавляемые элементы над существующим контентом;
- изменение высоты блоков после загрузки данных.

Исправление должно резервировать пространство до загрузки, а не скрывать измерение.

## INP

Проверяй:

- длинные JavaScript-задачи;
- тяжёлые обработчики кликов, scroll и input;
- синхронные измерения layout после изменений DOM;
- повторный рендер больших участков интерфейса;
- сторонние скрипты;
- отсутствие debounce/throttle там, где они оправданы.

## Формат результата

Для каждой метрики укажи:

- значение и источник;
- конкретный элемент/обработчик;
- корневую причину;
- минимальное исправление;
- способ повторного измерения;
- риск для дизайна или функциональности.
