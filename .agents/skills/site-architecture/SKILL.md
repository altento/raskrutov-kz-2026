# Site Architecture

## Цель

Создать понятную пользователю и поисковику структуру, где каждая индексируемая страница имеет отдельный интент, назначение и место в иерархии.

## Порядок

1. Собери существующие URL, трафик, позиции, обратные ссылки и конверсии.
2. Сопоставь семантические кластеры с существующими страницами.
3. Определи хабы, категории, услуги/товары, регионы, кейсы, статьи и служебные страницы.
4. Для каждой страницы зафиксируй:
   - название и тип;
   - родителя;
   - URL;
   - интент;
   - основной кластер;
   - индексируемость;
   - входящие и исходящие внутренние ссылки;
   - приоритет разработки.
5. Составь карту редиректов для удаляемых или объединяемых URL.

## Правила

- одна страница — один основной интент;
- важные страницы доступны обычно не глубже трёх кликов;
- URL короткие, стабильные и отражают иерархию без лишних повторов;
- не создавать страницу только ради одного низкочастотного варианта запроса;
- региональные страницы должны содержать реальную локальную ценность;
- кейсы, статьи и FAQ поддерживают коммерческие хабы внутренними ссылками;
- навигация и breadcrumbs согласованы с архитектурой.

## Выход

Выдай дерево сайта, таблицу страниц, правила URL, схему перелинковки, список редиректов и этапы внедрения. При миграции отдельно перечисли URL, которые нельзя потерять.
