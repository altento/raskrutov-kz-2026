# Schema Markup

## Принципы

1. Размечай только видимые и достоверные данные страницы.
2. Не выдумывай рейтинги, отзывы, цены, наличие, сотрудников и адреса.
3. Не дублируй конфликтующие сущности из разных скриптов.
4. Используй стабильные `@id` и связывай сущности через ссылки.
5. Проверяй итоговый DOM после выполнения JavaScript.

## Выбор типов

- `Organization` — компания и бренд.
- `LocalBusiness` или более точный подтип — локальная организация с фактическим адресом.
- `Service` — услуга.
- `Product` — конкретный товар, а не абстрактная категория.
- `BreadcrumbList` — путь страницы.
- `FAQPage` — только FAQ, видимый пользователю и соответствующий требованиям поисковиков.
- `Article`/`BlogPosting` — редакционный материал.
- `WebSite`/`WebPage` — при необходимости связать сайт и страницу.

## Порядок работы

1. Определи главную сущность страницы.
2. Собери данные из фактического контента и настроек проекта.
3. Создай один согласованный JSON-LD graph или несколько совместимых блоков.
4. Проверь синтаксис JSON.
5. Проверь Google Rich Results Test и Schema Markup Validator, когда применимо.
6. Проверь отсутствие расхождений с текстом страницы.

## Выход

Покажи готовый JSON-LD, место вставки, источники полей, ограничения rich results и сценарий проверки. Не обещай расширенный результат в выдаче.
