# Обязательные правила проекта

Перед изменениями прочитать `PROJECT_PROFILE.md`, применимые файлы `.cursor/rules/` и навык `.cursor/skills/build-static-seo-page/SKILL.md`.

1. Сначала проверить `git status`, структуру проекта и существующие компоненты. Сохранять пользовательские изменения.
2. Использовать существующий визуальный язык и проверенный шаблон нужного типа страницы.
3. Проектировать mobile-first. Проверять 360, 390, 412, 430 и 1280 px.
4. Контент первого экрана и H1 должны быть доступны из HTML без ожидания JavaScript.
5. Не ставить `loading="lazy"` на изображения первого экрана. Только вероятный LCP получает `fetchpriority="high"`.
6. Все изображения получают размеры; адаптивные изображения — `srcset`/`sizes`; ниже первого экрана — lazy-loading.
7. Не добавлять библиотеку, если задача решается текущим vanilla JavaScript.
8. Не выдумывать факты, цены, отзывы, рейтинги и реквизиты. Не размечать невидимое содержимое.
9. Писать прямо и уверенно, без риторических противопоставлений и сравнительных шаблонов.
10. После изменений выполнить `npm run quality:all`, проверить страницу визуально, консоль, формы и показать `git diff`.
11. Не выполнять commit, push и публикацию без отдельной команды.
