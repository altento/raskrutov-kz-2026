# Аварийные ситуации

## Cursor или ПК1 аварийно закрылся, lock остался

На ПК2:

```powershell
.\scripts\project-lock-status.ps1
```

Убедитесь, что владелец — PC1.

Физически убедитесь, что Cursor/работа на PC1 остановлены.

Только после этого:

```powershell
.\scripts\project-lock-release.ps1 -Force
```

Введите:

```text
RELEASE
```

## Lock принадлежит этому же ПК после перезапуска Cursor

Это нормально.

Новый промт на этом же ПК сможет продолжить работу.

Lock снимется автоматически после того, как:

- working tree станет чистым;
- commit будут отправлены в upstream;
- текущая ветка будет синхронизирована.

## Commit заблокирован

Проверьте:

```powershell
.\scripts\project-lock-status.ps1
```

Если lock FREE:

```powershell
.\scripts\project-lock-acquire.ps1
```

Затем commit.

## Push заблокирован на чужом ПК

Это ожидаемое поведение.

Не используйте `--no-verify`.

Перейдите на компьютер-владелец lock либо корректно освободите lock после завершения работы.

## GitHub недоступен

Система работает fail-closed: новый Cursor-промт может быть заблокирован.

Это специально, чтобы два ПК не начали писать одновременно при невозможности проверить GitHub.
